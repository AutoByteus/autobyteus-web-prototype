## Simulation boundaries

- Chat state, catalogs, streaming replies and created agents are browser-local synthetic fixtures (`prototype/chat/chat-fixtures.ts`, `composables/chat/usePrototypeChat.ts`). No production run, catalog, GraphQL or stream protocol is reproduced.
- Model names, descriptions, providers, workspace paths, chat titles and reply text are **illustrative**. Skill names mirror the user's skills package; their descriptions are shortened and illustrative. Tag semantics ("use this skill"; others stay available), `/` trigger and multi-tag are prototype defaults the user accepted in principle ("go") and remain open to confirmation.
- Runtimes: all five supported runtimes (AutoByteus, Codex App Server, Claude Agent SDK, Antigravity CLI, Grok Build) are available by default, matching the user's installation. Grok Build models are illustrative (the real catalog is reported by the Grok CLI).
- Team hand-off: the prototype cannot create a new team run from Chat; it opens the stored `team-run-001` (Product Review Team) through the product's own tree selection as a stand-in, with a toast explaining this.
- Run-view attachment uploads never complete in the prototype (spinner stays): the synthetic server does not simulate binary context-file uploads. Pre-existing baseline gap, reproduced on the unchanged baseline `5ae0fe1`. Chat attachments are prototype-native and complete.
- Voice: the mic only shows where the Voice Input extension is installed (desktop-app context); in that context the stored team run does not open (baseline fixture gap), so the run-view mic can be seen only in a running desktop app.
- Run-view model changes are prototype-local (update the focused run's model and show a toast).
- Scenarios: default; `chat_first_run` (no chats/recents); `chat_catalog_error` (first Antigravity CLI catalog load fails, Retry recovers); `chat_runtime_unavailable` (Grok Build not installed on this machine — shows `Not installed` with the reason on hover).

# Token Statistics Final Experience Story

## Experience Promise

A price-sensitive user opens Token Statistics and immediately sees the six
facts that explain the current period: Total tokens, Uncached input, Cached
input, Output, Estimated API cost, and Cache hit rate. The page then shows when
usage happened as one readable daily line and keeps exact contextual evidence
visible under `Detailed usage`. It never asks the user to interpret a
“driver,” an Input/Output ratio, or a prior-period change they did not request.

## Critical Story

1. **Orient:** Analytics is the default sibling of Run details; the Settings
   navigation item is the page title.
2. **Scope:** Choose a UTC range, open named Filters if needed, and switch
   Tokens/Cost. The current context remains visible and one result stays
   coherent.
3. **Understand:** Scan six equal peers. Total is primary through blue type,
   while cache-aware composition and spend remain equally reachable.
4. **See time:** Read the left/bottom axes and one open-top daily line. Each
   day is a point with exact accessible evidence; no top ceiling, bars, fill,
   stems, pace, or prior series competes.
5. **Verify:** Change the visible Runtime/Provider/Model grouping in Detailed
   usage and open a row for exact token components and cost status.
6. **Investigate runs:** Move to Run details, select creation dates and
   Task/Model beside Fetch, then inspect lifetime totals in the preserved
   hierarchy/table.
7. **Trust states:** Coverage, pricing, mixed/local cost, cache availability,
   loading, empty, and errors remain explicit. Missing truth is never rendered
   as zero.

## Completion Signal

The user can explain monthly/daily consumption, price exposure, cache
utilization, exact accounting, and run-level evidence without hidden primary
facts, misleading comparison, or export dependencies.
